MISE À JOUR DEPUIS 1.0

Gardez votre stockage. Le CMS migre vos données.

Avant de remplacer les fichiers, exportez une sauvegarde depuis la version 1.0 et copiez son dossier storage par SFTP. Activez la maintenance et fermez les autres onglets d’édition. Remplacez les fichiers du moteur avec ceux de ce pack, en conservant votre dossier storage et vos modules personnalisés. Vérifiez que PHP pdo_sqlite est actif.

Ouvrez ensuite admin.php, ou exécutez php bin/console.php migrate. La base storage/cms.sqlite est créée automatiquement avec pages, articles et révisions. Le compte, réglages et données d’extensions sont conservés. Aucune réinstallation n’est nécessaire.

Les originaux importés depuis la 1.1 gardent leur format et leur extension. Les médias déjà convertis en PNG en 1.0 restent en PNG, avec leurs octets existants. Les anciennes enveloppes PHP sont archivées dans storage/legacy/media.

Les journaux sont séparés : storage/logs/access.txt pour les accès PHP du CMS et storage/logs/error.txt pour les erreurs. Téléchargement depuis Sécurité. Gardez l’accès direct à storage bloqué par le serveur, ou placez ce dossier hors de la racine Web avec VV_STORAGE_PATH.

Avant de commencer

Sur un hébergement

PHP 8.3+ avec DOM, mbstring, fileinfo et pdo_sqlite. GD pour valider les images, ZIP pour les sauvegardes et modules. HTTPS activé. Mémoire recommandée : 256 Mo.

Compatible avec un déploiement par SFTP, à la racine ou dans un sous-dossier. Aucun Composer, Node ou MySQL à configurer.

Sur votre Mac

Le pack contient le CMS et son lanceur. Il nécessite PHP 8.3+ ou Docker déjà installé. Le moteur PHP n’est pas embarqué.

Le CMS reste accessible uniquement sur votre Mac tant que vous utilisez le lancement local fourni.

01 / HÉBERGEMENT PHP

Installer votre CMS en six étapes.

1

Copiez les fichiers

Décompressez l’archive puis copiez le contenu de voila-cms dans un dossier Web vide. Conservez .htaccess et .user.ini.

2

Autorisez le stockage

PHP doit pouvoir écrire dans storage. Pour installer des modules ZIP, autorisez aussi l’écriture dans content/themes et content/plugins. N’utilisez pas de droits 777.

3

Ouvrez l’installateur

Visitez https://votre-site.fr/install.php. Une clé aléatoire est créée dans storage/setup-key.php.

4

Récupérez votre clé par SFTP

Téléchargez le fichier, ouvrez-le comme du texte et copiez la clé après la première ligne PHP. Collez-la dans l’installateur. Le navigateur ne peut pas lire ce fichier.

5

Créez votre accès personnel

Choisissez votre nom de site, votre e-mail privé de gestion et un mot de passe de 14 à 72 octets. Aucun mot de passe par défaut.

6

Conservez votre code et publiez

Gardez hors ligne le code de récupération affiché une seule fois. L’installation se verrouille. Ouvrez « Mon profil & site », personnalisez votre profil, puis créez vos contenus.

Les mentions légales se créent comme des pages séparées avec vos informations réelles. Le CMS ne remplit pas automatiquement vos obligations ou les données de votre entreprise.
02 / SUR MAC

Choisissez votre méthode locale.

PHP disponible

Dans le dossier du CMS, ouvrez le Terminal :

php bin/console.php status
php bin/console.php install-key
php -d memory_limit=256M -d upload_max_filesize=64M -d post_max_size=70M -S 127.0.0.1:8787 router.php

Ouvrez http://127.0.0.1:8787. Ou utilisez Lancer-Mac.command. Si nécessaire : chmod +x Lancer-Mac.command. Laissez le Terminal ouvert ; Ctrl+C arrête le serveur local.

Docker disponible

Dans le dossier du CMS :

docker compose up -d --build
docker compose exec cms php bin/console.php install-key

Ouvrez http://127.0.0.1:8787. Pour arrêter : docker compose stop. Les volumes conservent les données et modules. Cette configuration de conteneur est fournie ; elle n’a pas été exécutée lors des tests du pack.

Vos thèmes, vos extensions, votre code.

Deux thèmes natifs et trois extensions sont livrés : Atelier personnel, Connexion PASS et Référencement essentiel. Le dossier sdk contient la documentation et deux exemples ZIP installables.

Les modules WordPress utilisent une autre API et nécessitent un portage. L’import reprend pages/articles et médias via un ZIP uploads local ; commentaires facultatifs modérés. La billetterie PASS, ses comptes, paiements et billets continuent de fonctionner sur l’installation PASS existante, reliée par URL.

Sauvegardez avant de modifier.

Le ZIP portable exporte les contenus, médias, réglages et données de modules. Votre mot de passe, les sessions et le code sont exclus. Une restauration conserve le propriétaire et crée un point complet avant remplacement. Trois points sont gardés sur le serveur.

Pour une copie complète comprenant le moteur et l’accès, sauvegardez également vos fichiers par SFTP dans un emplacement privé. Les sauvegardes peuvent contenir des notes et brouillons confidentiels.

Accès perdu : code de récupération depuis la connexion, ou console serveur php bin/console.php reset-owner. Extension en panne : admin.php?view=plugins&safe=1, ou php bin/console.php safe-mode.
