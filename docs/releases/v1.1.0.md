# VoilaVoila CMS 1.1.0 — SQLite, logs and original media

## English

- Pages/posts and revisions are now stored in real PDO SQLite tables.
- PHP access/error logs are separate plain text files with independent rotation and authenticated downloads.
- New JPG/JPEG/PNG/WebP/PDF uploads preserve their original bytes and extensions, with existing public/private media links retained.
- The automatic 1.0 migration preserves owner access, editorial data/revisions, settings and native plugin data. Legacy sources are kept; old portable backups remain importable.

**Upgrading from 1.0:** make both an editorial export and a complete private engine/storage backup, enable maintenance, enable `pdo_sqlite`, replace engine files while preserving storage/custom modules, then open admin or run `php bin/console.php migrate`. Do not reinstall. An image already converted to PNG by 1.0 remains PNG; its earlier JPEG cannot be recovered automatically.

[English upgrade guide](https://github.com/farhadtoor/voilavoila-cms/blob/main/docs/en/upgrade.md). PHP 8.3+ with DOM, mbstring, fileinfo and PDO SQLite; GD with required codecs for images; ZIP for archives. Raw storage must be denied by the real web server or placed outside the web root. Original image metadata, including EXIF, is preserved.

Attached: unchanged original installable ZIP and SHA-256 checksum. The supplied historical validation records 116 checks (50 HTTP, 35 features/migration, two failure/retry, 29 browser). The later GitHub-kit runner separately passed 87 checks on PHP 8.3.6. Actual GitHub CI, PHP 8.4/8.5 containers, production Docker and real hosting remain to be validated. No external security audit is claimed.

## Français

- Pages/articles et révisions désormais dans de véritables tables PDO SQLite.
- Journaux PHP accès/erreur en fichiers texte séparés, rotation indépendante et téléchargement authentifié.
- Nouveaux médias JPG/JPEG/PNG/WebP/PDF conservés avec octets et extensions d’origine ; liens et contrôle public/privé conservés.
- Migration automatique 1.0 conservant accès propriétaire, contenus/révisions, paramètres et données natives. Sources héritées gardées et anciens ZIP importables.

**Depuis la 1.0 :** faites un export et une copie complète privée moteur/stockage, passez en maintenance, activez `pdo_sqlite`, remplacez le moteur sans écraser stockage/modules personnalisés, puis ouvrez l’administration ou lancez `php bin/console.php migrate`. Ne réinstallez pas. Une image déjà convertie en PNG par la 1.0 reste PNG ; son JPEG antérieur ne peut pas être recréé.

[Guide français](https://github.com/farhadtoor/voilavoila-cms/blob/main/docs/fr/mise-a-jour.md). PHP 8.3+, DOM, mbstring, fileinfo et PDO SQLite ; GD avec les codecs nécessaires ; ZIP pour les archives. Le serveur doit refuser le stockage brut, ou celui-ci doit sortir de la racine Web. Les métadonnées EXIF des originaux sont conservées.

Pièces jointes : ZIP original inchangé et empreinte. Les rapports historiques comptent 116 contrôles ; le lanceur du kit GitHub a réussi séparément 87 contrôles sur PHP 8.3.6. CI GitHub réelle, conteneurs PHP 8.4/8.5, Docker de production et hébergement réel restent à vérifier. Aucun audit externe annoncé.
